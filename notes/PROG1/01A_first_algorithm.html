A first algorithm

From the concept of an algorithm to multiplication by repeated addition, through seven successive rewrites, all the way to the flowchart. Notes reconstructed from the 30 slides of the lesson, with worked examples, a step-by-step simulator, exercises and review questions.

The lesson in 7 points

  • Computer science studies algorithms, not computers: the computer is the tool, like the telescope for astronomy.
  • Algorithm = an ordered set of unambiguous and effectively computable operations that produces a result and halts in a finite amount of time.
  • Running example: computing m × n (with n ≥ 0) on a machine that can only add, assign and compare: repeated addition starting from the identity element 0.
  • You need two variables: an accumulator s (the partial sum) and a counter i (the additions already done).
  • Golden rule: check the condition first, then execute. If you check i = n after adding, with n = 0 the algorithm never terminates.
  • Notation: ← assigns, = compares. From jumps to numbered lines we move on to nested blocks (Begin/End), made visible by indentation.
  • The flowchart shows the flow of control. The goal of the course is to translate algorithms described in Italian into C, based on the model of the Von Neumann machine.

§1

What computer science is (and is not)

slides 2–4

Computer (calcolatore)

The word has changed meaning over time:

  • Originally a "computer" was a person who carried out calculations by hand, with pen and paper or with mechanical calculators. The photo on the slide shows exactly that: a room full of human computers.
  • Since the 1950s it has meant a programmable electromechanical device for carrying out even complex calculations. The second photo is the Programma 101 (1965) by Olivetti of Ivrea, advertised as "the do-it-yourself computer": one of the first desktop computers.

Computer science is not the science of computers. No more than astronomy is the science of telescopes, or surgery the science of scalpels.

The message: computer science studies algorithms, not devices. The computer is just the tool with which algorithms are executed.

§2

Algorithm: definitions and properties

slide 5

The slide gives two definitions. The first is intuitive; the second is the precise one you must be able to repeat.

Intuitive definition

A well-defined computational procedure, executable mechanically by a human being or by a machine, to obtain a given result (output) from certain starting data (input).

Precise definition · to memorise

An ordered set of unambiguous and effectively computable operations that, when executed, produces a result and halts in a finite amount of time.

Each keyword is a requirement. If one is missing, it is not an algorithm:

PropertyMeaningCounterexample
OrderedThe operations have a precise sequence: after each step you know which one comes next.A list of instructions in no order ("drain the pasta", "boil the water"…)
UnambiguousEach operation has only one possible interpretation."Add salt to taste"
Effectively computableEach operation can actually be carried out, with the means available to whoever executes it."Compute m × n" for a machine that can only add; "divide by 0"
Produces a resultAt the end there is an output.A procedure that neither returns nor communicates anything
Halts in finite timeIt terminates after a finite number of steps, for every allowed input.The second formulation of the multiplication with n = 0 (§8)

"Executable mechanically" means that executing it requires no intuition or creativity: you just follow the instructions. This is precisely what makes it possible to entrust it to a machine.

Where the word comes from

From the Persian mathematician Muḥammad ibn Mūsā al-Khwārizmī, who lived around the year 800. His book on calculation with Indian numerals (the digits 0–9 with the positional notation we use today) describes procedures for arithmetic operations. In the 12th-century Latin translation the text opens with the words "Dixit Algorizmi" ("thus spoke al-Khwārizmī"); the work is known by the title "Algoritmi de numero Indorum", which was given to it in the printed edition of 1857. The word "algorithm" derives from the author's Latinised name. A curiosity: the word "algebra" comes from another of his books (al-jabr).

§3

The model: everything is a number, one instruction per line

slides 6–7

In computer science everything is a number

  • Every piece of information a computer handles is represented as a number. Texts, images, sounds and instructions look like very different objects, but in memory they are all encoded as sequences of bits (numbers in binary).
  • An imperative program works by modifying numerical values stored in the state of the machine. The state is the set of values held in memory at a given moment.
  • Programming means describing how these values must be transformed, step by step.

Beyond the slides · examples

The letter A is stored as the number 65 (ASCII code), that is 01000001 in binary. A red pixel is the triple of numbers (255, 0, 0). You will soon see it in C: a character is a small integer.

Imperative programming

  • The program is an ordered sequence of instructions, in the form one line = one instruction.
  • Once line n has been executed, line n+1 is executed, unless otherwise specified. This is the sequential flow; jumps change it.
  • Examples of instructions for the machine:
    • assign a value to a variable;
    • add two variables and store the result in a third;
    • compare two variables;
    • jump to a line other than the next one, possibly under a certain condition.

A variable is a named container (s, i, m…) that holds a value, and that value can change during execution. The set of the values of the variables is the state.

§4

Designing an algorithm: the problem

slide 8

Problem: compute the multiplication of two integers m and n, with n ≥ 0. Before writing any step, four things must be settled:

Inputthe two values m and n
Outputthe value m × n
Stepsan unambiguous sequence of operations that the machine can execute
Terminationthe sequence reaches the output and halts after a finite number of steps

Assumption about the machine: it cannot multiply directly, but it can execute elementary operations: addition, assignment and comparison.

The key idea

Designing the algorithm means building the required result using only the available operations. An operation the machine does not have (multiplication) is reduced to one it does have (addition).

Beyond the slides · precondition

The constraint n ≥ 0 is called a precondition: it is what must hold for the input for the algorithm to work. Note that there is no constraint on m: it can even be negative (see exercise 3).

§5

The idea: repeated addition

slides 9–13

For n ≥ 0 the following holds:

m × n  =  m + m + … + m            ▷ n terms: I add m to itself n−1 times
s      =  0 + m + m + … + m        ▷ I start from the identity element 0: I add m exactly n times

The second form starts from the identity element of addition (0, because a + 0 = a). It is better for three reasons:

  1. All the steps are the same ("add m"), so they are repeated mechanically.
  2. The case n = 0 takes care of itself: zero additions, and the result stays 0 = m × 0.
  3. The number of additions is exactly n, not n−1: fewer chances of getting the count wrong.

What remains is to establish how to mechanically perform exactly n additions and then stop. We need something that counts.

Worked example: m = 4, n = 3

Slides 10–13 show the same thing: you start from the "initial partial sum" s = 0 with a closed fist, and with each addition you raise a finger. When three fingers are raised (that is, n), you stop.

§6

Accumulator, counter and "Program = Algorithms + Data Structures"

slide 14

Multiplication is carried out by repeatedly adding m to a partial sum s, initially 0, n times. To do this mechanically you need two tools:

ToolVariableWhat it is forIn the example by hand
Accumulatorskeeps track of the partial sumthe sheet of paper on which I do the additions
Counterikeeps track of the number of additions donethe fingers of the hand used for counting

This leads to two essential concepts of programming, which the course will often come back to:

  1. Data: the values the program operates on and the way they are organised.
  2. Procedures: the operations and processes that transform these data.

Niklaus Wirth

Program = Algorithms + Data Structures

A program is the combination of how we represent the data and how we define the operations that process them. Wirth, the creator of the Pascal language, gave this title to a book of his from 1976 (Algorithms + Data Structures = Programs).

Beyond the slides · two patterns you will see everywhere

Accumulator: a variable initialised to the identity element of the operation (0 for sums and counts, 1 for products) and updated at each step. Counter-controlled loop: a variable that starts from an initial value, advances by 1 at each repetition and decides when to stop. Almost every exercise on loops uses at least one of them.

§7

From an idea to an algorithm: seven versions

slides 15–26

The heart of the lesson is the way the algorithm is refined one step at a time: each version fixes a flaw of the previous one. Knowing why you move from one version to the next matters as much as knowing the final version.

V1The idea in wordsslide 15
1. First of all, set the accumulator s to the identity value 0,
   and set the counter i to 0.
2. Add m to s exactly n times, updating the counter i
   (additions done) and at the same time the accumulator s
   (partial result).

Flaw: step 2 is semantically complex. It hides the repetition and the check inside it, so it is not an elementary step that the machine can execute.

V2Elementary steps, check at the endslide 16
1. set s to 0 (identity value) and i to 0
2. add m to the accumulator s
3. add 1 to the counter i
4. if i = n: the additions are finished and s is the total,
   otherwise repeat from step 2

Flaw: it works with m = 4, n = 3, but the check comes after the addition. With n = 0 it still performs one addition, then i = 1 and the condition i = n will never be true: it does not terminate (§8).

V3The check firstslide 21
[1] set the accumulator s to 0 and the counter i to 0
[2] if i = n the additions are finished and s is the total:
    we terminate. Otherwise we continue.
[3] add m to the accumulator s
[4] add 1 to the counter i
[5] go back to line 2

What changes: the check comes before the operations. With n = 0 it terminates immediately with s = 0. The lines are numbered because they serve as jump targets.

V4Formal notationslide 22
[1] s ← 0,  i ← 0
[2] if i = n the algorithm terminates, otherwise
[3]     s ← s + m        ▷ add m to s
[4]     i ← i + 1        ▷ increment the counter i by 1
[5]     go back to line 2

What changes: ← is assignment ("the value on the right goes into the variable on the left"), = is comparison. The text after ▷ is a comment. The indentation of [3]–[5] is intentional: it shows that those operations depend on the condition in line [2].

V5"Terminates" is too strong: the End instruction and jumpsslides 22–24
[1] s ← 0,  i ← 0
[2] if i = n then jump to line 6, otherwise
[3]     s ← s + m
[4]     i ← i + 1
[5]     jump to line 2
[6] End

What changes: saying that "the algorithm terminates" is too strong, because after the multiplication we might want to execute other instructions. The special instruction End is introduced, and the jump to a numbered instruction is used both to repeat and to exit.

V6Begin/End blocksslides 24–25
[1] Begin Algorithm
[2]     s ← 0,  i ← 0
[3]     Begin Conditional Repetition
            if i = n then jump to line 7, otherwise   ▷ conditional jump
[4]         s ← s + m
[5]         i ← i + 1
[6]         jump to line 3                            ▷ unconditional jump
[7]     End Conditional Repetition
[8] End Algorithm

What changes: for uniformity, blocks are delimited by pairs of special instructions Begin/End (on the slides: Inizio/Fine). A distinction is made between the conditional jump (line 3 → 7, taken only if i = n) and the unconditional jump (line 6 → 3, always taken).

V7Structured version, without line numbersslide 26
Begin Algorithm
    s ← 0,  i ← 0
    Begin Conditional Repetition
    if i = n jump to End Conditional Repetition, otherwise
        s ← s + m
        i ← i + 1
        jump to Begin Conditional Repetition
    End Conditional Repetition
End Algorithm

What changes: the structure makes it possible to eliminate line numbers: jumps point to the beginning or the end of a block. Structured programming languages organise instructions into nestable blocks, and indentation makes visible the hierarchy and which block each instruction belongs to. This is exactly the shape the while loop will have in C (§11).

§8

The bug in the n = 0 case

slides 17–20

Algorithm V2 was built from "test" values (m = 4, n = 3). But does it also work for other inputs? The slide tries a special case: n = 0, where the expected result is 0 (because m × 0 = 0).

Trace of V2 with m = 4, n = 0

StepInstructionsiCheck i = n
1s ← 0, i ← 000not checked yet
2s ← s + m40—
3i ← i + 141—
4if i = n …411 = 0? NO → repeat
7if i = n …822 = 0? NO → repeat
…………i > n forever: it does not terminate

The problem is the order: V2 first updates s and i and then compares i with n. If n = 0, the algorithm will never terminate (always i > n). Moreover, even if it stopped, s would already be different from 0: the result would be wrong.

Fix: you must first check that the counter i is less than n, and only then, if so, perform the addition. With V3 and m = 4, n = 0: s ← 0, i ← 0, then 0 = 0? YES → end with s = 0. Correct.

The design principle of the course · slide 20

First check the conditions, and only then execute (the first of a series of) operations.

"It will stay with us for the rest of this course."

Matters in the exam · slide 20

Verbatim from the slide: "Handling the initial case is a typical source of errors, even in the exam." ("La gestione del caso iniziale è una tipica fonte di errori, anche in sede d'esame.") When you write a loop, always ask yourself: what happens if the loop must not be executed even once?

Beyond the slides · how to check an algorithm

Besides the "normal" case used to design it, always try the edge cases: n = 0 (no repetitions), n = 1 (just one), m = 0, negative m, and what happens if the precondition is violated (n < 0). You can do this in the simulator below.

§9

Flowchart (diagramma di flusso)

slides 28–29

Before moving on to a real programming language, the lesson introduces an intermediate representation: the flowchart.

  • It highlights the flow of control: it shows graphically the possible execution sequences between the instructions.
  • Unlike the structured representation (V7), it does not make the nesting of blocks explicit: it directly follows the links between the instructions.
  • It has historically been widely used and is sometimes useful for visualising control, but modern languages prefer to express nested control structures directly.
  • Oval: Begin and End
  • Rectangle: operations (assignments)
  • Diamond: condition, with YES / NO exits
  • Arrow: the instruction that comes next

In the multiplication flowchart the two jumps are easy to see: the YES exit of the diamond towards End is the conditional jump (taken only if i = n), and the arrow that goes from the block of additions back to the diamond is the unconditional jump (always taken).

    What you will do in this course

    Now we have an idea of how to implement the multiplication algorithm on a real computer. The aim of the course is to learn to implement elementary algorithms (very simple ones) in the C language, that is, to translate algorithms specified in Italian into C.

    TermMeaning (notes of slide 30)
    Implementingconcretely realising a procedure using a programming language, starting from its logical definition
    Translatingthis is the goal of Programming I. In the Algorithms exam, the aim will instead be to analyse and design new algorithms

    To do this you need a model of computation that can be executed by a mechanical or electronic computer: the Von Neumann machine, the topic of the next part.

    Beyond the slides · a preview of Von Neumann

    In the Von Neumann machine a memory holds both the data and the instructions of the program. The CPU always repeats the same cycle: it fetches the next instruction, decodes it and executes it. A register (the program counter) indicates which instruction to execute: normally it moves on to the next one ("line n+1", slide 7). A jump does nothing more than change its value. Our pseudocode with line numbers is therefore very close to how the machine really works.

    §11

    Preview: multiplication in C

    beyond the slides

    C will arrive in the next lessons, but seeing now where version V7 leads helps you understand why the lesson insists so much on blocks and conditions.

    #include <stdio.h>
#include <assert.h>

int main(void) {
    int m = 4, n = 3;      // input (hard-coded for now)
    assert(n >= 0);        // precondition
    int s = 0;             // accumulator: starts from the identity element
    int i = 0;             // counter of the additions done

    while (i != n) {       // first I check the condition...
        assert(s == m * i);// invariant (§12): holds at every check
        s = s + m;         // ...then I execute: s ← s + m
        i = i + 1;         // i ← i + 1
    }                      // end of block: back to the while check
    assert(s == m * n);    // postcondition

    printf("%d x %d = %d\n", m, n, s);
    return 0;
}

    Checked with gcc -Wall -Werror (the options used in the exam in previous years): it prints 4 x 3 = 12, and it also works with 5 × 0, 0 × 7, −2 × 3. assert(cond), from <assert.h>, stops the program with an error if the condition is false: in the course it is used to write pre- and postconditions directly in the code.

    Classic C pitfall

    Writing if (i = n) instead of if (i == n): the first assigns n to i, it does not compare them. Without options the compiler silently accepts it (it is valid C); with -Wall gcc warns ("suggest parentheses around assignment used as truth value"), and with -Wall -Werror, the options used in the exam in previous years, the program does not compile. The ← / = distinction seen in slide 22 is there precisely so that you do not confuse the two.

    People often write while (i < n) instead of while (i != n). With n ≥ 0 the two versions do exactly the same things. With a negative n, i < n is false straight away and the loop terminates (with a wrong result), whereas i != n never terminates. In both cases the precondition must be respected.

    Version V2 (check after), on the other hand, corresponds to the C do { … } while (…); loop, which executes the body at least once. With do-while loops the initial case always needs extra care.

    §12

    Why the algorithm works

    beyond the slides

    The slides check the algorithm by trying out some cases. You can also reason about why it always works. These concepts will come back when you study the correctness of loops.

    Invariant: a property that is always true at the moment of the check

    Every time you reach the check i = n ?, s = m × i holds:

    • At the start: s = 0 and i = 0, and indeed 0 = m × 0.
    • After one iteration: if s = m × i held before, after s ← s + m and i ← i + 1 we have s + m = m × i + m = m × (i + 1). The property is preserved.
    • On exit: you exit when i = n, so s = m × n. That is exactly the desired result.

    Termination

    The quantity n − i starts from n ≥ 0 and decreases by 1 at each iteration: after exactly n iterations it is 0 and the loop stops. This is where the precondition is needed: with n < 0 the quantity starts negative, i grows and will never reach n (try it in the simulator with the "4 × −2" preset).

    How much it costs

    With input n: the condition is evaluated n + 1 times (n times "NO", once "YES"), the body is executed n times, that is n additions on s and n increments of i. The time grows in proportion to n. This kind of counting will be central in Algorithms and Data Structures.

    §13

    Pitfalls and typical mistakes

    summary

    To avoid

    1. Checking the condition after executing the body when the body might never need to be executed (the n = 0 case). This is the V2 mistake.
    2. Forgetting to initialise the accumulator and the counter. In C an uninitialised local variable has an indeterminate value (it is not necessarily 0): using it before assigning it a value is an error. Only global and static variables start at 0.
    3. Initialising with the wrong identity element: 0 for sums and counts, 1 for products (see exercise 5).
    4. "Off-by-one" counting errors: m + m + … + m has n terms but n − 1 additions. Starting from 0, the additions are exactly n.
    5. Confusing assignment and comparison: ← versus = in pseudocode, = versus == in C.
    6. Ignoring the precondition: with n < 0 the algorithm does not terminate. If the exercise does not guarantee it, it must be handled.
    7. Testing only the sample case used for the design. Always try n = 0, n = 1, m = 0, negative m.
    8. Swapping the order of the instructions in the body when one uses the value updated by the other (see exercise 6).

    Rules for exam exercises (past years, the same in all channels)

    • Iterative functions: a single return statement; use sentinel variables to combine conditions; break, switch, case and static are forbidden, and so, in general, are constructs not seen in class.
    • Recursive functions: no loops, neither for nor while; pay attention to the type of recursion required.
    • Compilation: -Wall -Werror, so even a single warning prevents compilation.
    • Marking: "passing all the tests is a necessary but not sufficient condition", because the code is also read. 31 or 32 points are worth 30 cum laude.

    The link with structured programming

    These rules apply the idea of §7. break and multiple returns are jumps that leave a block "through the side". In V7, instead, you leave the repetition only through its condition. In the exam the loop must stop because of the condition (for example i < n && !found), not because of a jump.

    Beyond the slides · a preview of an exam exercise

    Here is where the principle "check first, then execute" leads when applied to an array (a topic of the coming weeks): is there a negative element among the first aLen elements of a?

    bool exists = false;              // initial case: nothing exists in an empty array
size_t i = 0;                     // counter
while (i < aLen && !exists) {     // first I check, then I execute; no break
    exists = (a[i] < 0);
    i = i + 1;
}
return exists;                    // a single return

    For "all the elements are positive", on the other hand, the sentinel starts from true, because in an empty array the property holds. Getting this initial value wrong is the initial-case mistake.

    Execute version V6 (slide 25) with m = 5, n = 2. Write a table with the line executed, s, i and the outcome of the check. How many times is the condition evaluated? How many additions on s?

    2 · Bug hunt basic

    Execute V2 (check after) with m = 3, n = 1 and then with m = 3, n = 0. In which case does it work? Why does V2 "seem" correct if you only try it with n ≥ 1?

    Solution

    With n = 1: s ← 0, i ← 0; s ← 3; i ← 1; 1 = 1? YES → s = 3. Correct.

    With n = 0: s ← 3, i ← 1, 1 = 0? NO, then s = 6, i = 2… it does not terminate.

    V2 executes the body at least once. This is right only if at least one addition is needed, that is n ≥ 1. The case n = 0 is the only allowed case (n ≥ 0) in which the body must not be executed, and that is exactly where it goes wrong. Moral: always test the initial case.

    3 · Negative numbers intermediate

    (a) Does the algorithm work with m = −2, n = 3? (b) And with m = 2, n = −3? (c) Modify it so that it works for any integer n, knowing that the machine can also compute the opposite of a number (x ← −x).

    Solution

    (a) Yes: s takes the values 0, −2, −4, −6, and −6 = −2 × 3. There is no constraint on m.

    (b) No: i takes the values 0, 1, 2, … and will never be equal to −3. The precondition n ≥ 0 is violated and the algorithm does not terminate.

    (c) Use the identity m × n = (−m) × (−n): if n is negative, change the sign of both, and you are back to the case n ≥ 0.

    Begin Algorithm
    if n < 0 then  m ← −m,  n ← −n     ▷ now n ≥ 0
    s ← 0,  i ← 0
    Begin Conditional Repetition
    if i = n jump to End Conditional Repetition, otherwise
        s ← s + m
        i ← i + 1
        jump to Begin Conditional Repetition
    End Conditional Repetition
End Algorithm

    Example: 2 × (−3) becomes (−2) × 3 = −6. Correct.

    4 · Integer division by repeated subtraction intermediate

    Write an algorithm that, given m ≥ 0 and n > 0, computes the quotient q and the remainder r of the integer division m ÷ n using only addition, subtraction, assignment and comparison. Run it with m = 14, n = 4. What happens if n = 0?

    Solution 
    Begin Algorithm
    q ← 0,  r ← m                      ▷ r is "what is left to divide"
    Begin Conditional Repetition
    if r < n jump to End Conditional Repetition, otherwise
        r ← r − n                      ▷ I take away one n
        q ← q + 1                      ▷ I count how many times I have taken away n
        jump to Begin Conditional Repetition
    End Conditional Repetition
End Algorithm

    Trace (q, r): (0, 14) → (1, 10) → (2, 6) → (3, 2), then 2 < 4 → end: q = 3, r = 2, and indeed 14 = 3 × 4 + 2.

    The check comes before the body: if m < n it exits immediately with q = 0, r = m (for example 3 ÷ 5 → q = 0, r = 3). Same principle as slide 20.

    If n = 0, r never decreases and the loop does not terminate: it is "division by zero". That is why the precondition requires n > 0. Here q acts as a counter, but unlike in the multiplication you do not know in advance how many repetitions you will do.

    5 · Power intermediate → hard

    (a) Compute p = mⁿ (n ≥ 0) assuming that the machine can multiply. What value does p start from? (b) Challenge: what if the machine could only add (with m ≥ 0)?

    Solution

    (a) Same pattern as the multiplication, but the accumulator starts from the identity element of multiplication, that is 1. If it started from 0 the result would always be 0.

    Begin Algorithm
    p ← 1,  i ← 0
    Begin Conditional Repetition
    if i = n jump to End Conditional Repetition, otherwise
        p ← p × m
        i ← i + 1
        jump to Begin Conditional Repetition
    End Conditional Repetition
End Algorithm

    With m = 2, n = 3: p takes the values 1, 2, 4, 8. With n = 0 it gives 1 (by convention m⁰ = 1).

    (b) Replace p ← p × m with the multiplication algorithm: one repetition inside the other (nested loops). Here you can see why blocks and indentation are indispensable.

    Begin Algorithm
    p ← 1,  i ← 0
    Begin Conditional Repetition                      ▷ outer: n times
    if i = n jump to End Conditional Repetition, otherwise
        s ← 0,  j ← 0                                 ▷ compute p × m with additions
        Begin Conditional Repetition                  ▷ inner: m times
        if j = m jump to End Conditional Repetition, otherwise
            s ← s + p
            j ← j + 1
            jump to Begin Conditional Repetition
        End Conditional Repetition
        p ← s
        i ← i + 1
        jump to Begin Conditional Repetition
    End Conditional Repetition
End Algorithm

    Each "jump" refers to the block it is part of: indentation is what makes this reading unambiguous. You need a second counter (j) and a second accumulator (s), reset to zero at each outer iteration.

    6 · Sum of the first n numbers and order of the instructions intermediate

    Write an algorithm that computes 1 + 2 + … + n (n ≥ 0). Then answer: what does it compute if the two instructions in the body are swapped?

    Solution 
    Begin Algorithm
    s ← 0,  i ← 0
    Begin Conditional Repetition
    if i = n jump to End Conditional Repetition, otherwise
        i ← i + 1          ▷ first I advance the counter...
        s ← s + i          ▷ ...then I add it: I add 1, 2, …, n
        jump to Begin Conditional Repetition
    End Conditional Repetition
End Algorithm

    With n = 4, (i, s): (0, 0) → (1, 1) → (2, 3) → (3, 6) → (4, 10). Indeed 1 + 2 + 3 + 4 = 10 = 4 × 5 / 2.

    If you swap them (s ← s + i and then i ← i + 1) you add 0, 1, 2, 3 = 6: that is the sum of the numbers from 0 to n − 1, a classic "off-by-one" error. Here the counter is also used as data, so the order matters.

    7 · Flowchart basic

    Draw the flowchart of exercise 4 (division). Indicate which arrow is the conditional jump and which is the unconditional jump.

    Solution

    Begin → rectangle q ← 0, r ← m → diamond r < n ?. From the diamond: YES exit → End (conditional jump); NO exit → rectangle r ← r − n, q ← q + 1 → arrow that goes back to the diamond (unconditional jump).

    It is the same drawing as for the multiplication: only the contents of the blocks and the condition change. Many algorithms with a loop have this shape.

    8 · Fewer additions hard

    With m, n ≥ 0 the algorithm performs n additions: for 3 × 1000 it performs a thousand. Modify it so that it performs min(m, n). You need to swap the contents of two variables: why does m ← n, n ← m not work?

    Solution

    Since m × n = n × m, if n > m it is worth swapping m and n before the loop. The swap requires a temporary variable t:

    if n > m then
    t ← m          ▷ save m
    m ← n
    n ← t
▷ ...then the multiplication algorithm as before

    With m ← n, n ← m the first assignment overwrites m, and the second copies into n the value that n already had: in the end both hold the old n. The swap with a temporary variable is one of the exercises of the first labs.

    §16

    Review questions

    self-check

    Answer out loud or in writing, then open the answer.

    What is an algorithm? List and explain its properties.

    An ordered set of unambiguous and effectively computable operations that, when executed, produces a result and halts in a finite amount of time. Ordered: a precise sequence. Unambiguous: only one interpretation. Effectively computable: whoever executes it can actually carry it out. Produces a result: there is an output. Terminates: a finite number of steps for every allowed input.

    What does the sentence about telescopes attributed to Dijkstra mean?

    That computer science is not the science of computers, just as astronomy is not the science of telescopes: the computer is the tool. Computer science studies algorithms: their properties (correctness, efficiency), their physical realisation (computers), their linguistic realisation (programming languages) and their applications (software).

    Where does the word "algorithm" come from?

    From the name of the Persian mathematician al-Khwārizmī (around 800), author of a book on calculation with Indian numerals that describes procedures for arithmetic operations.

    Why do we say that "in computer science everything is a number"?

    Because every piece of information (text, image, sound, instruction) in the memory of the computer is encoded as a number, that is, as a sequence of bits. An imperative program works by modifying numerical values in the state of the machine; programming means describing how to transform them step by step.

    What are the characteristics of imperative programming?

    The program is an ordered sequence of instructions, one per line. When line n is finished, line n+1 is executed, unless indicated otherwise (jumps). Typical instructions: assign a value to a variable, add two variables putting the result in a third, compare two variables, jump to another line (possibly under a condition).

    What must be defined when you design an algorithm?

    Input (the starting data), output (the result), steps (an unambiguous sequence of operations that the machine can execute) and termination (the output is reached and execution stops after a finite number of steps). You also need to know which operations the machine has available.

    Why is it better to start from s = 0 in the multiplication?

    Because 0 is the identity element of addition: s = 0 + m + … + m requires exactly n additions, all the same, and the case n = 0 immediately gives the right result (0) without special treatment. Writing m + m + … + m, the additions would be n − 1 and the case n = 0 would make no sense.

    What is the difference between an accumulator and a counter?

    The accumulator s holds the partial sum, like the sheet of paper on which you do the additions. The counter i holds the number of additions already done, like the fingers of your hand, and is used to decide when to stop.

    "Program = Algorithms + Data Structures": who said it and what does it mean?

    Niklaus Wirth. A program combines the way we represent and organise the data with the procedures (algorithms) that transform them.

    Why is the second formulation (V2) wrong? What principle can be drawn from it?

    Because it updates s and i and only then checks whether i = n. With n = 0 it still performs one addition, i becomes 1 and the condition i = n will never be true: the algorithm does not terminate. Principle: first check the conditions, and only then execute the operations. Handling the initial case is a typical source of errors, even in the exam.

    What is the difference between a conditional and an unconditional jump? Where are they in the algorithm?

    The conditional jump happens only if a condition is true: "if i = n jump to line 7" (V6, line 3). In the flowchart it is the YES exit of the diamond towards End. The unconditional jump always happens: "jump to line 3" (V6, line 6). In the flowchart it is the arrow that goes from the block of additions back to the diamond.

    Why does the slide say that talking about "termination" is too strong?

    Because the multiplication might be only one part of a larger algorithm, after which we want to execute other instructions. Instead of "the algorithm terminates", you jump to the end of the block (End instruction) and execution continues.

    What are the Begin/End pairs and indentation for?

    They delimit blocks, which can be nested one inside the other. Thanks to the structure, jumps can refer to the beginning or the end of a block, so line numbers are no longer needed. Indentation makes visible the hierarchy of the blocks and which block each instruction belongs to. This is the idea behind structured languages.

    What is the difference between a flowchart and a structured representation?

    The flowchart shows graphically the flow of control (the possible execution sequences) by following the links between the instructions, but it does not make explicit the nesting of blocks. The structured representation organises the instructions into nested blocks. Modern languages prefer the latter.

    What is the difference between low-level and high-level languages?

    Low-level languages are close to the machine (machine language, assembly). High-level languages are closer to natural language (FORTRAN, C, Java, Python).

    What is the goal of Programming I compared with the Algorithms course?

    In Programming I you learn to implement elementary algorithms in C, that is, to translate algorithms specified in Italian into C. In the Algorithms exam the aim will be to analyse and design new algorithms. The reference model of computation is the Von Neumann machine.

    Lesson glossary

    terms
    Algorithm
    An ordered set of unambiguous and effectively computable operations that produces a result and halts in a finite amount of time.
    Input / Output
    Starting data / result produced.
    Instruction
    A single command for the machine; in imperative programming, one per line.
    Variable
    A named container whose value can change during execution.
    State
    The set of values stored in the machine at a given moment.
    Assignment ( ← )
    Puts the value of the expression on the right into the variable on the left: s ← s + m. In C it is written =.
    Comparison ( = )
    Checks whether two values are equal: i = n. In C it is written ==.
    Accumulator
    A variable that collects the partial result (here s).
    Counter
    A variable that counts the repetitions already executed (here i).
    Identity element
    A value that does not change the result of the operation: 0 for addition, 1 for multiplication.
    Termination
    The property of halting after a finite number of steps.
    Initial case / edge cases
    Initial case: the input for which the loop must not be executed even once (for example n = 0), a typical source of errors. Edge cases: the "extreme" inputs to try every time, such as n = 0, n = 1, m = 0, negative m.
    Conditional jump
    A jump executed only if a condition is true.
    Unconditional jump
    A jump that is always executed.
    Block
    A group of instructions delimited by Begin/End; blocks can be nested.
    Indentation
    Shifting lines to the right to show which block each instruction belongs to.
    Structured programming
    Organising the program into nestable blocks instead of jumps to numbered lines.
    Flowchart
    A graphical representation of the flow of control (ovals, rectangles, diamonds, arrows).
    Program
    A description of an algorithm by means of a programming language.
    Programming language
    A set of formally defined words and rules for programming a computer.
    Implementing
    Concretely realising a procedure in a programming language, starting from its logical definition.
    Von Neumann machine
    A model of a computer with a memory that contains both data and program, executed by a CPU one instruction at a time. Next topic.
